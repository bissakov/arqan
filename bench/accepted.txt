# Regressions this tree has argued for, one per line:
#
#   case | label | metric | cap | reason
#
# A label of * covers every step of the case. The cap is what review accepted,
# so a row that grows past it fails as any other would, and an entry that
# stops matching is reported as unused: once a cost is in the baseline the
# entry is dead and belongs deleted, since the cap would otherwise go on
# excusing whatever lands in that case next. Metrics are the names a report
# carries: cpu_per_unit_ms, priv_kb, growth_kb.
#
# A bare cap is a ratio and a `+` cap is an absolute rise in the metric's own
# units. Take whichever the cost is. A slower machine takes proportionally
# longer to do the same extra work, so time is a ratio: the worst measured
# against the parent commit times 1.2, the room a step needs to repeat on a
# loaded machine and no more. Worst means worst of every machine the gate runs
# on, the CI runner included: the extra work and the step it lands in do not
# slow down by the same factor, so a runner half the speed of a workstation
# does not report half the ratio, and a cap read off one machine is a cap for
# one machine.
#
# A fixed cost is absolute instead, because its ratio describes the step it
# landed in rather than itself: a megabyte mapped into a step that grew 0.7 MB
# by itself reads as x2.4, and into one that grew 0.25 MB as x5.5. So is a
# step whose own cost is under the floor, where there is no denominator worth
# dividing by: a tenth of a millisecond is the machine, and a ratio against it
# reports the machine.
#
# The list is empty. It is meant to be: an entry is a cost this tree decided
# was worth paying, and it is deleted in the change that follows the one that
# added it.
